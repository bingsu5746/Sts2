# 캐릭터 4 — 마검사 설계 메모

> 자료: `magic-sword-research.docx` (세계 명검·마검 백과 보고서, 44개 항목, 2026-09-30)

## 컨셉
여러 마검을 캐릭터 주변에 띄워 놓고 상황에 따라 쓰는 검사.

## 확정
- 여러 마검이 동시에 떠서 각자 작동한다. 한 번에 한 자루만 쓰는 방식이 아니다.
- 슬롯 구조는 Defect 오브와 비슷해서 폐기.
- 마검은 **소환 카드**로 불러낸다. 선천성 · 0코스트 · 소멸 · 영구.
  - 소유한 마검 전부를 한 번에 소환한다.
  - 새 마검 획득·강화는 이 카드의 상태를 바꾸는 방식으로 처리한다.
  - 손패 한 자리를 차지하는 것은 허용.
- 소유 상한이 있고, 유물·이벤트로 1~2자루만 늘릴 수 있다.
- 시작은 약한 마검 1자루. 대가가 거의 없고 성능이 낮으며 끝까지 키워 쓰는 성장형.

## 제안 (미확정)
- 마검마다 대가, 마기 수치 누적 시 폭주
- 검마다 다른 사건 트리거 (공격 시 / 피격 시 / 턴 시작 시 등)
- 상한 기본 3, 최대 4~5 (임시값)
- 상한이 찼을 때 교체, 교체 시 강화 상태 소실
- 검 목록은 런 단위 저장소에 두고 카드는 읽어서 표시

## 소스에서 확인할 것
- Clone 인챈트가 Eternal과 별개 규칙인지 (복제 방지)
- Soul's Power 인챈트 제외 방법
- 런 단위 저장, 검 시각 배치 구현

## 남은 결정
1. 검 리스트 (유래 · 트리거 · 대가)
2. 시작 검 효과와 성장 경로
3. 시작 덱 구성
4. 마검 획득처와 상한 확장 방법

## 검 획득 연출 (임시)
- 검을 얻을 때 그 검의 기원을 보여 주는 연출을 띄운다.
- 방식 후보: 원화 3~4장 + 문구 슬라이드(추천) / Godot 애니메이션 / 동영상(.ogv)
- 첫 획득 시 전체 연출, 이후 짧은 이펙트만. 건너뛰기 가능.
- 문구는 `magic-sword-research.docx`의 "이름·유래", "특징" 칸 활용.
- 소스 확인 필요: 소환 카드 상태 변경 지점에서 보상·이벤트 화면 위에 씬을 띄울 수 있는지.

## 핵심 규칙 (사용자 결정, 2026-09-30)
- 대가는 검마다 다르다. (공통 마기·폭주 게이지 제안은 채택하지 않음)
- 마검마다 전용 카드군이 있다. 소환한 마검에 해당하는 카드군을 쓸 수 있다.
- 마검을 얻으면 그 마검 관련 기본 카드·좋은 카드를 몇 장 받는다.
- 이후는 STS2처럼 카드 보상·상점으로 카드를 모은다.
- 카드 보상과 상점에는 현재 보유한 마검 관련 카드만 나온다.
- 마검 획득처: 상점(매우 낮은 확률), 고유 이벤트.

### 미정 (Claude가 제기한 질문)
- 소환 전에는 해당 검 카드를 못 쓰는지 (소환 카드가 선천성 0코스트라 사실상 1턴째 해금)
- 공용 카드(검과 무관한 기본 공격·방어)가 있는지
- 떠 있는 마검 자체에도 패시브 효과가 있는지, 아니면 카드 해금 역할만 하는지
- 획득 확률이 낮을 때 그람 하나로 끝나는 런을 막을 장치(보장 획득 지점)가 필요한지
- 검을 교체·잃을 때 그 검의 카드는 어떻게 되는지

## 핵심 규칙 2차 (사용자 결정, 2026-10-01)
1. 1막 보스 처치 후 마검 획득 이벤트가 나온다. (그람만으로 끝나는 런 방지)
2. 공용 카드(검과 무관한 카드)도 다양하게 있다.
3. 자아가 있는 검 하나만 턴마다 자동 공격한다 → 오니마루 구니쓰나 (보고서: 주인의 손을 거치지 않고 스스로 움직여 요괴를 벰). 나머지 검은 주변에 떠 있고, 카드로 바꿔 가며 공격하는 연출용.
4. 소환 카드는 필수가 아니다. 복제 문제가 있으면 카드 없이 처리해도 된다. 목적은 "마검 추가가 쉬운 구조".
5. 검을 교체·잃으면 그 검의 카드는 없애는 방향 (세부 미정).

### Claude 제안 (미확정)
- 4번: 보유 마검 목록을 **시작 유물**에 저장(`[SavedProperty]`), 전투 시작 훅(`Hook.BeforeCombatStart`)에서 검을 띄움. 같은 유물이 보상·상점 필터도 담당. 소환 카드가 없으니 복제·Soul's Power 문제가 사라짐.
- 5번 처리 후보: 덱에서 제거(`CardPileCmd.RemoveFromDeck`) / 공용 카드로 변환(`CardCmd.Transform`, `TransformToRandom`) / 덱에 남기되 사용 불가

## 검 교체·상실 시 카드 처리 (사용자 결정, 2026-10-01)
- 검을 잃으면 그 검의 카드를 덱에서 제거하고, 다시 얻으면 자동으로 전부 돌아온다.
- 구현 근거: 기존 유물 `PaelsTooth`가 같은 동작을 함 — `ToSerializable()`로 카드를 `[SavedProperty] List<SerializableCard>`에 저장 → `CardPileCmd.RemoveFromDeck` → 나중에 `CardModel.FromSerializable` + `CardPileCmd.Add(…, PileType.Deck)`로 복귀. `SerializableCard`가 강화 단계·인챈트·속성값을 함께 저장하므로 강화 상태도 유지될 것으로 보임.
- 소유 상한: 기본 3 (임시)

## 결정 (2026-10-01, 검 전환·강화)
- 검 전환: **C 방식** — "현재 검"이 있고, 어느 검의 카드든 언제나 사용 가능, 카드를 쓰면 현재 검이 그 검으로 바뀜. 현재 검은 지속 효과를 줌. 공용 "전환" 카드로도 전환 가능. 오니마루는 현재 검과 무관하게 매 턴 자동 공격.
- 전환 보너스: 고민 중
- 공용 카드 비율: 미정
- 1막·2막 확정 이벤트 후보 3자루: 완전 무작위
- **마검 카드는 개별 강화 불가.** 대신 휴식처에 새 선택지 "마검 강화" 추가 → 성공하면 그 마검의 카드 전부가 조금씩 강해짐.
- 마검마다 강화 이벤트(스토리)가 다르다.

### 구현 근거 (sts2.dll 확인)
- `CardModel.MaxUpgradeLevel`이 virtual(기본 1), `IsUpgradable`은 `CurrentUpgradeLevel >= MaxUpgradeLevel`이면 false → 마검 카드에서 0으로 두면 강화 불가.
- 휴식처 선택지 추가: `Hook.ModifyRestSiteOptions` → `AbstractModel.TryModifyRestSiteOptions`. 기존 유물 `Girya`(들어올리기, 최대 3회), `Shovel`, `PaelsGrowth`가 같은 방식 → 시작 유물이 "마검 강화" 선택지를 넣으면 됨.
- 카드가 강화 단계를 유물에서 읽어 수치를 바꾸는 방식은 아직 미확인.

### 미정
- "성공하면"의 의미: 실패 확률이 있는지
- 강화 단계 수, 단계당 버프 폭
- 기존 휴식처 "강화"는 공용 카드에만 쓰이게 됨

## 마검 강화 선택지 (사용자 결정, 2026-10-01)

- 도박 강화: 2단계 또는 3단계 상승을 시도. 실패 시 디버프, 매우 낮은 확률로 마검이 박살남
